## 1. Purpose and scope

This document describes every Mongoose model that Linda registers: its file, MongoDB collection, fields, references
and indexes. It covers 49 models in 26 schema files. WhatsApp session data is **not**
stored in MongoDB; see section 3.

## 2. Database

- Connection: `MONGODB_URI` (default `mongodb://localhost:27017/damac-hills-2` in `api-server.js`).
- Used by: the API servers (all models) and the bot (campaigns, daily limits, message logs, consent, communication
  queue).
- MongoDB is required for campaign safety limits and message reservations; without it campaign sending is unavailable.

## 3. Data stored outside MongoDB (local only)

| Data | Location | Notes |
|---|---|---|
| WhatsApp sessions (LocalAuth browser profiles) | `sessions/session-<clientId>/` | Local disk only; never sent to MongoDB or the API |
| Device and account metadata | `session-state.json`, `config/` | Atomic writes; not tracked in Git |
| Terminal feature counters | `data/feature-usage.json` | Usage counters shown in the terminal |

## 5. Known issues

| ID | Issue | Impact |
|---|---|---|
| DB-1 | `schemas/index.js` defines its own `Cluster` and `Property` schemas and registers them only if no model with that name exists (`mongoose.models.X \|\| mongoose.model(...)`). `ClusterSchema.js` and `PropertySchema.js` define different shapes for the same names. | The shape in use depends on import order. The tables below show the dedicated files' shapes. Consolidation is recommended. |
| DB-2 | `express-server-inmemory.js` declares its own `PropertyOwner` and `PropertyContact` schemas for the in-memory development server. | Development only; may differ from the production schemas. |
